# Changelog

All notable changes to Nova are documented in this file.

## [0.1.0] - 2026-08-21

### Added

- Real mouse activity observation through the off-by-default `mouse_activity` permission and a Windows Native bridge using `GetLastInputInfo` for activity/idle transitions plus a separate on-demand `GetCursorPos` read for authorized action-time consumers. The observer validates screen bounds, never publishes or stores movement/click history, keeps cursor coordinates out of diagnostics, updates ephemeral WorldModel engagement state, and stops immediately on revocation. Sandbox tests, strict builds, and structural no-history checks pass; live Windows validation remains deferred while no Windows host is connected.
- Real keyboard activity observation through the off-by-default `keyboard_activity` permission and a Windows Native bridge using `GetLastInputInfo` plus explicitly registered `RegisterHotKey` bindings. The observer emits only active/idle transitions and catalog-defined `observer.keyboard.hotkey_triggered` identities, rejects unknown fields and unregistered IDs, stops on revocation, and never captures or logs keystrokes. The ephemeral World Model now exposes bounded keyboard engagement state without durable memory promotion. Sandbox tests, strict builds, and structural no-keylogging checks pass; live Windows validation remains deferred while no Windows host is connected.
- Local privacy-safe structured diagnostics across the CommunicationBus, NamedPipe transport, API Gateway, PermissionGrantStore, orchestration, RuntimeApplication, and browser observer. The shared logger emits bounded UTC JSONL records with severity, stable event names, correlation IDs where applicable, recursive redaction, local retention, and injectable in-memory sinks for tests; payloads, credentials, raw action parameters, page content, entered text, keystrokes, clipboard/notification bodies, screenshots, and local pipe paths are excluded.
- Real browser metadata observation through the off-by-default `browser_metadata` permission and visible Manifest V3 extension surface: tab open/close/activation/navigation callbacks, Chrome Native Messaging, local named-pipe API Gateway routing, strict HTTP(S) URL normalization that removes credentials/query/fragment data, bounded titles, per-tab coalescing, immediate revocation purge, persisted `permissions.browser_excluded_domains` validation and hot reload, and task-bound memory indexing that stores metadata only. Page content, forms, passwords, payments, DOM automation, screenshots, OCR, vision fallback, and automatic Windows host registration remain outside this slice. Sandbox tests and static packaging checks pass; live browser/Windows validation remains deferred while no Windows host is connected.
- Real event-based Windows notifications observation with approved `notifications_metadata` and `notifications_content` permissions, metadata-only downgrade behavior, sensitive messaging/authentication-source exclusion, event coalescing, immediate revocation shutdown, task correlation, and task-bound ObservationIndexer support that strips unapproved body text. Sandbox tests pass; live Windows validation remains deferred until a Windows host is available.
- Real event-based Windows clipboard observation with approved `clipboard_metadata` and `clipboard_content` permissions, metadata-only downgrade behavior, sensitive-source exclusion, pending-event coalescing, immediate revocation shutdown, task correlation, and task-bound ObservationIndexer support that strips unapproved content. Sandbox tests pass; live Windows validation remains deferred until a Windows host is available.
- Task-bound accessibility-state reads through Windows UI Automation, returning matched element identity, control type, enabled/offscreen state, and exposed value; UI Automation actions now require matching post-action accessibility evidence before reporting completion. The read path is exposed through isolated preload IPC and the Runtime Executor/Verifier tool boundary. Sandbox tests pass; live Windows validation remains deferred until a Windows host is available.
- Task-bound Windows desktop-agent integration with separate `screen` and `desktop_control` permissions, one-shot full-screen/focused-window PNG capture, actual native dimensions, bounded base64 validation, structured Windows UI Automation `invoke`/`set_value`, immediate World Model focus checks, resource-locked Executor/Verifier routing, explicit destructive confirmation, isolated preload IPC, and no raw-frame persistence. Sandbox gates pass; live Windows bridge validation is deferred until a Windows host is available.
- Non-destructive Windows source-checkout bootstrap via `pnpm install:windows`, which installs the frozen workspace, builds the Electron desktop package, creates user-scoped Nova data directories, refuses non-Windows hosts, and deliberately does not register services, install third-party software, delete data, or start observers.
- Real Windows system inventory collection for hardware, current-user AppX and uninstall-registry applications, running processes, model-storage availability, and counts restricted to explicitly granted filesystem scopes; unavailable AVX signals remain `unknown` rather than being fabricated.
- Native Windows application/process and window observer using WinEvent hooks, WMI process notifications, monitor/virtual-desktop metadata, bounded title-only payloads, explicit `applications` plus `windows` permissions, and immediate revocation shutdown; the observer feeds a session-only World Model focus hierarchy with bounded recent transitions and causal correlation IDs.
- Safe workspace-code execution capability `nova.workspace-code`, wired through the existing Executor, PermissionManager, and ResourceManager: registered runtimes only, canonical workspace containment, no shell, bounded stdout/stderr, enforced timeouts, exit-code evidence, mandatory confirmation, non-idempotent retry behavior, and lock cleanup.
- Explicit task-bound observer adoption into Working Memory through the real desktop-persistent MemoryStore, with no automatic task assignment, normalized application/window metadata, and removal of native handles, window contents, and file paths from persisted payloads.
- Real desktop Task Monitor pagination and cancellation through isolated Electron IPC and the authenticated internal gateway, with authoritative TaskManager refresh, retry/waiting metadata, queued-task cancellation, and an explicit error when an already-running executor process cannot be interrupted.
- Distributed Full-Peer task placement through RuntimeApplication with an explicit owning-device field, origin-device defaults, opt-in resource/capability reassignment, retry re-scoring, and protection for tasks waiting on user confirmation.
- Validated capability/provider configuration records and visible personalization preference records with vault-only credential references, atomic updates, individual or full reset, and real desktop Provider Settings and Settings forms wired through the isolated Electron IPC bridge.
- TypeScript monorepo foundations for shared contracts, runtime services, memory, observers, state, and Electron desktop surfaces.
- Planner, executor, verifier, task management, tools, model routing, workflows, plugins, providers, credentials, diagnostics, backup, restore, and operational recovery boundaries.
- Cross-device pairing, sync, logical clocks, distributed Full Peer task scheduling, voice wake-claim coordination, channels, multi-agent coordination, and incident lifecycle management.
- Trusted-device inventory listing from the pairing manager, returning only paired identity, runtime mode, public key, trust state, and pairing timestamp; short-lived channel tokens remain outside the inventory contract, and Device Management now exposes explicit confirmation-backed access revocation that also clears live session-continuity presence, capabilities, remote-control preapprovals, and active sessions.
- Remote-control session and command inputs now reject blank identifiers, signatures, and content before approval or transport execution, returning the existing fail-closed security error contract; session TTLs and pre-approval windows must be positive safe integers, pre-approval device IDs cannot be blank, and a live session identifier cannot be replaced by a duplicate request.
- Secure pairing offer creation and challenge-confirmed completion are now composed by RuntimeApplication and exposed through dedicated isolated desktop IPC channels; invalid or unavailable pairing inputs fail closed with typed security errors, blank offer or completion fields are rejected before trust changes, pairing TTLs must be positive safe integers, active pairing codes cannot be overwritten by collisions, the negotiated runtime mode is bound into the signed challenge payload, and replacing an existing trusted identity requires explicit unpair first.
- CrossDeviceSyncManager is now composed by RuntimeApplication and reachable through explicit desktop sync and flush controls, reporting logical checkpoints, applied changes, pushed changes, and transport errors without silently initiating network activity.
- The permission-first AndroidCompanionManager is now composed by RuntimeApplication and exposed through isolated desktop IPC for individual companion permission status/grant/revoke operations, capability checks, and explicit foreground-service start/stop before background use; bundled access is not introduced, and unavailable companion runtimes fail closed.
- The existing EmailAssistant is now composed by RuntimeApplication and exposed through isolated desktop IPC for privacy-safe email reads, draft validation, and draft-first sending that requires explicit confirmation unless an exact automation rule applies; unavailable email providers fail closed and provider failures remain retryable.
- The existing CalendarAssistant is now composed by RuntimeApplication and exposed through isolated desktop IPC for upcoming-event reads, conflict-aware proposals, and calendar creation that blocks conflicts and requires explicit confirmation for external effects; unavailable calendar providers fail closed.
- The existing ChannelManager is now composed by RuntimeApplication and exposed through isolated desktop IPC for identity-aware inbound receipt, authorized outbound delivery, and channel media-capability lookup; unauthorized senders and destinations remain fail-closed, and message content is excluded from diagnostics.
- The existing BackgroundAssistant is now composed by RuntimeApplication and exposed through isolated desktop IPC for explicit briefing generation and delivery; disabled proactive mode, permissioned sources, and confirmation-required items remain respected, with no autonomous irreversible action introduced.
- AdaptivePersonalization is now bound to RuntimeApplication’s shared configuration store and exposed through isolated desktop IPC for inspectable proposal creation, pending-list inspection, explicit approval or dismissal, and individual/all resets; proposals never mutate active configuration before approval, routing suggestions never silently alter policy, and no model-weight changes are introduced.
- IncidentManager is now composed by RuntimeApplication and exposed through isolated desktop IPC for the documented Detect → Triaged → Mitigated → Resolved → Postmortem lifecycle and timeline inspection, with strict identifier/detail/severity validation and owner/timestamp evidence on every entry.
- RunbookManager handling is now available through RuntimeApplication and isolated desktop IPC for explicitly injected startup, provider, and sync recovery operations; unconfigured recovery fails closed with a typed security error rather than inventing or silently executing operations.
- CapabilityRegistry inspection and live provider enable/disable, priority, and routing-policy edits are now exposed through RuntimeApplication and isolated desktop IPC with strict validation; registry diagnostics continue to exclude credentials, prompts, responses, and arbitrary provider payloads.
- LocalModelManager catalog discovery is now available through RuntimeApplication and isolated desktop IPC using a validated HardwareProfile; this slice only reports bounded catalog metadata and lifecycle status, and does not initiate downloads, model loads, or file writes.
- VoicePipeline lifecycle start, stop, barge-in, and state inspection are now available through RuntimeApplication and isolated desktop IPC; raw audio, transcript submission, and speech content remain outside this bridge until a dedicated permissioned media boundary is implemented.
- PluginDiscovery proposals are now available through RuntimeApplication and isolated desktop IPC for vetted capability-gap search, pending inspection, and explicit confirm/decline decisions; this slice never installs or executes a plugin automatically, and preserves HTTPS, trust, and capability filtering.
- BackupManager creation, pre-update snapshots, and non-destructive owner-scoped restoration are now available through RuntimeApplication and isolated desktop IPC; the existing encryption, checksum, retention, and cross-user rejection rules remain enforced, while restore never applies state automatically.
- RestoreManager staging and live-state application are now available through RuntimeApplication and isolated desktop IPC; staged state must be verified and the apply operation requires explicit confirmation, with unconfirmed restores leaving live state unchanged.
- UpgradeManager execution is now available through RuntimeApplication and isolated desktop IPC behind explicit confirmation and strict non-negative version validation; forward-only migrations retain snapshot, verification, and rollback behavior, while unconfirmed upgrades perform no adapter operations.
- RepairManager inspection and safe-fix application are now available through RuntimeApplication and isolated desktop IPC; inspection-only mode is the default, unsafe issues remain reported rather than auto-fixed, and repair failures remain retryable.
- On-demand device capability negotiation through RuntimeApplication and isolated desktop IPC, with per-request status responses for Supported, Not supported, Permission denied, and Degraded capabilities before remote execution; failed remote functional probes now downgrade the capability to Degraded for subsequent requests.
- Named-pipe CommunicationBus, API Gateway, real RuntimeApplication composition root wired into Electron main, authoritative task-status IPC retrieval and renderer refresh, Prisma/SQLite immutable task checkpoints with write-before-acknowledgment and crash recovery remapping, Planner/Permission Manager/Executor/Verifier Runtime Task Coordinator, correlated task-progress events, authenticated local REST task submission/status/list/cancel, memory search, memory-record lookup with lineage, bounded Knowledge Graph queries, permission listing/update endpoints, configuration listing/section-update endpoints, real webhook registration through the authenticated external event boundary, and authenticated WebSocket event streaming with live delivery, topic authorization, bounded replay, and backpressure handling, authenticated REST tool listing and plugin-tool registration with independent scopes, signed webhook delivery with retry and health handling, secure Electron preload bridge, guided onboarding, performance-budget evaluation, integration tests, simulations, chaos tests, filesystem E2E tests, and documentation-link verification.
- Production repository documentation, contribution infrastructure, security policy, issue forms, pull-request guidance, and CI workflow.
- Electron desktop host persistence bootstrap with a stable per-user workspace UUID, canonical `memory/structured/nova.db` path, forward migration application, Prisma `TaskCheckpointStore` injection, durable gateway submission, and orderly Prisma shutdown.
- Real Groq OpenAI-compatible LLM provider adapter with vault-reference credential resolution, authenticated model health checks, chat-completion translation, strict response validation, and deterministic-router compatibility; no provider key is stored inline or exposed to the renderer.
- Cross-platform IPC hardening with deterministic Windows named-pipe mapping and explicit readiness handshaking, plus Windows filesystem-observer path identity preservation while retaining canonical security checks.
