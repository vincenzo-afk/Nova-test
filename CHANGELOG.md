# Changelog

All notable changes to Nova are documented in this file.

## [0.1.0] - 2026-08-21

### Security

- Pairing-offer responses now use a bounded renderer projection that excludes the short-lived channel credential while preserving non-secret pairing metadata.
- Plugin record, enable, and disable responses now use bounded lifecycle summaries and no longer expose manifests, entry points, or raw granted permission lists to the renderer.
- Plugin discovery and pending-proposal responses now use bounded identity and aggregate-count summaries and no longer expose source URLs, signature keys, capability arrays, or raw permission scopes to the renderer.
- Desktop task pause and cancellation now route through RuntimeApplication-owned confirmation gates before TaskManager or scheduler mutation, preserving canonical task lifecycle errors and transitions.
- Desktop task responses now expose only bounded lifecycle summaries; user goals, correlation IDs, step history, workflow context, and internal reasons remain outside the renderer boundary.
- Confirmed workflow-resume responses now expose only workflow identity, lifecycle state, checkpoint identity, and an aggregate completed-node count; completed node IDs and execution context remain outside the renderer boundary.
- Confirmed backup restoration now returns only a success acknowledgement to the renderer; restored snapshot contents remain in the privileged runtime.
- Confirmed email and channel-send responses now return bounded delivery receipts without message bodies, content, recipient addresses, or chat identifiers.
- Restore preparation now keeps staged state in privileged main-process memory and exposes only a one-time opaque handle to the renderer for confirmed apply.
- Setup responses now expose only wizard progress steps; host inventory, filesystem scopes, hardware details, and configuration payloads remain outside the renderer boundary.

### Added

- The desktop runtime now seeds the complete documented provider-capability catalog, exposing deterministic Unconfigured records for LLM, vision, speech-to-text, text-to-speech, embeddings, OCR, reranking, messaging channels, and remote control before providers are installed.
- Windows deployment now includes a credential-safe service-registration CLI that creates an auto-start, user-scoped NOVA host service with restart recovery; packaged host path and account are explicit inputs, while the account password is requested only at execution time and never stored in the registration plan.
- Windows deployment now includes explicit service unregistration through `pnpm unregister:windows-service`; it validates the service name, requires an exact interactive confirmation phrase before invoking `sc.exe delete`, and never removes Nova memory or configuration data.
- Windows deployment now includes an explicit `pnpm uninstall:windows` workflow that removes the service before optionally deleting the user-scoped `%LOCALAPPDATA%\\Nova` data root; retention or deletion is selected explicitly, deletion requires confirmation, and unsafe data roots are rejected.
- Desktop task submission now durably creates tasks through `RuntimeTaskCoordinator`, queues successful submissions at interactive priority in the composed local `TaskScheduler`, and dispatches them without allowing failed persistence to reach the scheduler; Planner, Permission Manager, Executor, and Verifier remain authoritative.
- Runtime upgrades now support paired pause/resume lifecycle hooks: in-flight work is paused after the pre-update snapshot and before migrations, verified upgrades resume work afterward, and failed upgrades roll back before attempting resumption; partial hook configuration fails closed.
- MCP server configuration is now validated as bounded lifecycle records with deterministic stdio or Streamable HTTP transport, no mixed command/endpoint forms, safe endpoints, and vault-only authentication references; validation remains separate from protocol connection and discovery.
- The runtime now provides a local MCP lifecycle manager for Discovered → Pending approval → Connected → Disabled transitions, explicit confirmed removal, and bounded removal results without credential references; it does not claim to connect, discover tools, or start external MCP processes.
- Desktop MCP management is now exposed through the permission-first IPC path with explicit confirmations for all mutations and renderer projections limited to server ID, label, lifecycle state, and transport; commands, endpoints, and vault references remain outside the renderer boundary.
- Electron packaging now provides a per-user NSIS installer configuration and `pnpm package:windows` workflow that includes the compiled desktop, runtime workspace packages, Prisma client, and migrations without changing the non-destructive source bootstrap.
- Windows browser integration now provides an explicit `pnpm register:windows-browser-host` workflow that materializes a placeholder-free Chrome Native Messaging manifest and registers it under the current user’s HKCU registry key; it validates the extension ID and absolute host/manifest paths, refuses non-Windows execution, and does not install the extension or start observation.
